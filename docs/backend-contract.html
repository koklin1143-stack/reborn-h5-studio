v14 数据与服务边界

当前只有可持久化的本地前端。GitHub Pages 托管页面，不存储、共享或审核用户作品。所有能力由 ArchiveService.capabilities 明确标为未接入。

状态 schema 7

集合作用
drafts / works可编辑草稿、已保存私有稿；lineageId 为设计身份，rewardRootId 为贯穿编辑副本的奖励身份；imageId 引用独立 Blob。
creators / sources项目示例、本机创作者；素材名、类型、权利声明、verified=false。个人图像声明不等于第三方核验。
publications独立作品快照、creatorId、sourceId、主题、展示状态、三项确认与版本 / 时间 / 仅本机范围。撤回不删除私有稿，重新展示创建新快照。
galleryLikes / galleryCollections作品 ID 组成的本机喜好集合。没有虚构他人点赞数；不产生入选或积分。
submissions主题、作品快照与同意记录；reviewState、selectionState、productionState 分离，不用一个「已投稿」代表审核或量产。
ledger / growth积分流水以 type:rewardRootId 防重，保存计分规则版本、当时快照与可追溯 source；成长事件独立记录保存、灵感、模拟公开、撤回等动作。
pointsPolicy / ui本地演示规则；排序、类别、滚动、当前作品与编辑返回来源。版本 6 迁移不补发积分，旧记录格式不识别时暂停写入。

命令与查询接口

archive-service.js 提供 list(state, filters)、get(state, id)、publish(state, workId, consent)、withdraw(state, publicationId)、inspire(state, publicationId)、toggle(state, kind, id)。界面通过协调器复制候选状态，在一个 IndexedDB 事务成功后再显示成功。失败保留原状态。当前适配器为同步本地领域命令，接远程服务时需将协调器改为等待服务端结果，并处理并发版本冲突。

后端必须承担的责任

  • 真实登录、作品归属、访问权限、私有文件和图片上传安全、合法来源证明。
  • 实际公开发布授权：展示范围、署名、改编许可、期限、撤回、隐私和内容审核。当前三项本机确认不构成正式对外授权协议。
  • 服务端搜索与分页，点赞收藏幂等，内容版本与多端同步，不能相信前端传入的计数、作者或精选状态。
  • 服务端积分账本、幂等键和有效行为验证；客户端不应具有发分、选入或核准量产权限。
  • 审核、入选与生产各自的受控状态转换、馆方权限、审计记录、版权及工艺审核。

需要人工确认

馆方正式奖励规则、现金激励预算与发放、文化权益、版权授权文本与撤回政策、审核责任人及流程、真实月度主题、示例素材的馆藏对应和工艺量产标准。当前均不作承诺。
